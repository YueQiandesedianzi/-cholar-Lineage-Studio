复制后按实际流程填写。

```markdown
# 分工协作日志（Git 式模拟）

## 团队与角色

| 角色 | 成员代号 | 职责 | 分支 |
|---|---|---|---|
| ① 文献管理员 | lib | 导入/去重建库 | feat/corpus |
| ② 提取工程师 | ext | 按模板抽取证据卡片 | feat/extraction |
| ③ 核验审稿人 | rev | 逐条核验 | review/cards |
| ④ 章节作者甲 | A | §1–§3 | feat/sec-1-3 |
| ④ 章节作者乙 | B | §4–§6 | feat/sec-4-6 |
| ⑤ 主编 | EIC | 审核、合并、§7–§8 | main |

## 提交时间线

### 阶段 1 · 文献库（①）
c101  lib  导入文献 N 篇（检索命中 → 去重 → 入库）
c102  lib  Merge feat/corpus → main

### 阶段 2 · 证据抽取（②）
c201  ext  定义统一模板：……
c202  ext  抽取证据卡片 C01–Cxx
c206  ext  提交 MR #1：请求核验

### 阶段 3 · 核验（③）
c301  rev  通过 Cxx…
c302  rev  修订 Cxx（见 R1）
c303  rev  驳回 Cxx（见 R2）

### 阶段 4 · 分章节写作（④）
c401  A  草拟 §1 …
c411  B  草拟 §4 …
c4xx  提交 MR #2 / #3

### 阶段 5 · 审核与合并（⑤）
c501  EIC  审核 MR #2 → 内联评论
c505  EIC  Merge feat/sec-* → main
c507  EIC  撰写 §7–§8
c508  EIC  打标签 v1.0

## 内联评论（⑤ → 作者）

- `§x.x`：评论——"……"（作者已补/已调整）

## 合并冲突

### K1 · 冲突描述
- 分支 A：……
- 分支 B：……
- 解决方式：保留主干 + 手动合并；统一术语为"……"

## 证据追溯校验（合并前）

| 检查项 | 结果 |
|---|---|
| 正文实质性论断均有证据卡片支撑 | ✅ |
| 被驳回卡片未被作为已核验证据引用 | ✅ |
| 修订卡片引用的是"人工修正后"论断 | ✅ |
| DOI 均来自检索结果，无杜撰 | ✅ |
| 定位字段如实标注 | ✅ |

## 最终产物

- v1.0 = 综述正文
- 证据链 = 证据卡片与核验
- 流程 = 本日志
```
